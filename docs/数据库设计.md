# Spring Nest 数据库设计

## 概述

Spring Nest 使用 Supabase (PostgreSQL) 作为云端数据库，实现用户数据的跨设备同步。数据库设计遵循最小权限原则，通过 Row Level Security (RLS) 确保用户只能访问自己的数据。

## 表结构详解

### 1. profiles (用户资料)

存储用户的基本信息，与 Supabase Auth 的 `auth.users` 表一一对应。

| 列名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | `UUID` | PRIMARY KEY, REFERENCES auth.users(id) ON DELETE CASCADE | 用户 ID，关联 Supabase Auth |
| `username` | `TEXT` | NOT NULL, DEFAULT '' | 用户昵称 |
| `bio` | `TEXT` | DEFAULT '' | 个人简介 |
| `avatar_url` | `TEXT` | DEFAULT '' | 头像 URL |
| `created_at` | `TIMESTAMPTZ` | NOT NULL, DEFAULT now() | 创建时间 |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL, DEFAULT now() | 更新时间 |

**索引:**
- `id` (主键索引，自动创建)

**触发器:**
- 新用户注册时自动创建 profile 记录
- 更新时自动刷新 `updated_at`

---

### 2. favorites (用户收藏)

存储用户收藏的游戏和工具。

| 列名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PRIMARY KEY, GENERATED ALWAYS AS IDENTITY | 自增主键 |
| `user_id` | `UUID` | NOT NULL, REFERENCES profiles(id) ON DELETE CASCADE | 所属用户 |
| `item_id` | `TEXT` | NOT NULL | 收藏项 ID (如 '2048', 'calculator') |
| `item_type` | `TEXT` | NOT NULL, CHECK (item_type IN ('game', 'tool')) | 收藏类型 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL, DEFAULT now() | 收藏时间 |

**索引:**
- `idx_favorites_user_id` ON `user_id` — 按用户查询收藏
- `idx_favorites_user_item` ON `(user_id, item_id)` UNIQUE — 防止重复收藏

---

### 3. game_scores (游戏分数)

记录用户在各游戏中的成绩。

| 列名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PRIMARY KEY, GENERATED ALWAYS AS IDENTITY | 自增主键 |
| `user_id` | `UUID` | NOT NULL, REFERENCES profiles(id) ON DELETE CASCADE | 所属用户 |
| `game_slug` | `TEXT` | NOT NULL | 游戏标识 (如 '2048', 'memory', 'whackamole') |
| `score` | `INTEGER` | NOT NULL | 分数/成绩 |
| `metadata` | `JSONB` | DEFAULT '{}' | 额外数据 (如用时、步数等) |
| `created_at` | `TIMESTAMPTZ` | NOT NULL, DEFAULT now() | 记录时间 |

**索引:**
- `idx_game_scores_user_game` ON `(user_id, game_slug)` — 按用户和游戏查询
- `idx_game_scores_leaderboard` ON `(game_slug, score DESC)` — 排行榜查询

**metadata 字段说明:**

| 游戏 | metadata 内容 |
|---|---|
| 2048 | `{ "best_score": 2048 }` |
| 记忆翻牌 | `{ "best_steps": 24, "best_time": 45 }` |
| 打地鼠 | `{ "best_score": 30 }` |

---

### 4. user_settings (用户设置)

存储用户的个性化设置。

| 列名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PRIMARY KEY, GENERATED ALWAYS AS IDENTITY | 自增主键 |
| `user_id` | `UUID` | NOT NULL, REFERENCES profiles(id) ON DELETE CASCADE, UNIQUE | 所属用户 (唯一) |
| `theme` | `TEXT` | NOT NULL, DEFAULT 'system', CHECK (theme IN ('light', 'dark', 'system')) | 主题偏好 |
| `language` | `TEXT` | NOT NULL, DEFAULT 'zh', CHECK (language IN ('zh', 'en')) | 语言偏好 |
| `notifications` | `JSONB` | DEFAULT '{"email": true, "push": true, "updates": false, "promotions": false}' | 通知设置 |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL, DEFAULT now() | 更新时间 |

**索引:**
- `idx_user_settings_user_id` ON `user_id` UNIQUE — 每用户一条记录

---

### 5. tool_usage (工具使用记录)

记录用户使用工具的行为，用于统计分析。

| 列名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PRIMARY KEY, GENERATED ALWAYS AS IDENTITY | 自增主键 |
| `user_id` | `UUID` | NOT NULL, REFERENCES profiles(id) ON DELETE CASCADE | 所属用户 |
| `tool_slug` | `TEXT` | NOT NULL | 工具标识 (如 'calculator', 'pomodoro') |
| `used_at` | `TIMESTAMPTZ` | NOT NULL, DEFAULT now() | 使用时间 |
| `metadata` | `JSONB` | DEFAULT '{}' | 额外数据 |

**索引:**
- `idx_tool_usage_user_id` ON `user_id` — 按用户查询
- `idx_tool_usage_tool_slug` ON `tool_slug` — 按工具统计
- `idx_tool_usage_used_at` ON `used_at` DESC — 按时间排序

---

## 数据流

### 用户注册流程

```
用户注册 → Supabase Auth 创建 auth.users 记录
         → 触发器自动创建 profiles 记录
         → 触发器自动创建 user_settings 记录 (默认值)
```

### 数据同步流程

```
┌─────────────┐     ┌──────────────┐     ┌─────────────┐
│   浏览器     │     │   Supabase   │     │  PostgreSQL  │
│  (React App) │     │   Client SDK │     │   Database   │
└──────┬──────┘     └──────┬───────┘     └──────┬──────┘
       │                   │                     │
       │  1. 用户操作       │                     │
       │  (收藏/设置/分数)  │                     │
       │                   │                     │
       │  2. 调用 SDK       │                     │
       │  supabase.from()  │                     │
       │──────────────────→│                     │
       │                   │  3. RLS 验证         │
       │                   │  检查 user_id        │
       │                   │────────────────────→│
       │                   │                     │
       │                   │  4. 执行 SQL         │
       │                   │  INSERT/UPDATE/SELECT│
       │                   │←────────────────────│
       │                   │                     │
       │  5. 返回结果       │                     │
       │←──────────────────│                     │
       │                   │                     │
       │  6. 更新 UI        │                     │
       │                   │                     │
```

### 离线优先策略

```
┌──────────────────────────────────────────────┐
│              应用启动                         │
│                                              │
│  1. 检查 localStorage 是否有缓存数据          │
│     ├── 有 → 立即渲染 (离线可用)              │
│     └── 无 → 显示加载状态                     │
│                                              │
│  2. 尝试从 Supabase 拉取最新数据              │
│     ├── 成功 → 更新 localStorage + 渲染       │
│     └── 失败 → 使用 localStorage 缓存         │
│                                              │
│  3. 用户操作时                                │
│     ├── 先写入 localStorage (即时响应)         │
│     └── 异步同步到 Supabase (后台同步)         │
│                                              │
└──────────────────────────────────────────────┘
```

## 数据迁移策略

从 localStorage 迁移到 Supabase 的步骤:

1. 用户首次登录 Supabase 时，检查 localStorage 中是否有旧数据
2. 如果有，将 localStorage 数据批量写入对应的 Supabase 表
3. 迁移完成后，标记迁移状态，后续使用 Supabase 作为数据源
4. localStorage 保留为离线缓存
